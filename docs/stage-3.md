目标：评委不登录、不填表，打开首页即可阅读完整示例，点击一次即看到规则变化。本阶段完成后暂停，阶段 4 再实现创建与认领页面。

## 已实现

- 首屏默认四人宿舍示例，包含空间、有效期、示例人数、五条规则及各自执行接口、宣誓句预览。明确标为“示例，尚未通过”，日期保留［日期］，没有伪造真实通过记录。
- 三个空间各有三套规则，使用已经生成的九套 JSON 数据；只切换本地状态，不访问后端或模型。换批在同一空间循环，三个空间可直接切换。
- “看一个四人宿舍示例”恢复第一套并将焦点和视口带到宪法卡。当前示例写入地址片段，刷新恢复；非法示例片段回到默认。地址片段只代表静态示例，不是房间分享功能。
- 桌面左右布局，1280×800 默认卡五条及宣誓句在首屏内。小屏优先展示示例，保持完整文字，允许纵向滚动。空间选择列在卡片之后；键盘顺序与手机阅读顺序一致。
- 原生按钮、清晰焦点、选中状态、简短读屏通知、减少动态效果支持。JavaScript 关闭时仍有完整默认卡和操作说明。
- 保留前后端分离和 Next.js 转发配置；没有为了静态示例改用会破坏 API 转发的静态导出。

## 本地运行

```powershell
Set-Location 'D:\比赛\Qoder\源代码'
npm.cmd --prefix frontend run dev
```

打开 http://127.0.0.1:3000 。本阶段首页不需要启动后端。若已有生产预览占用 3000，先停止该预览再运行开发服务。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check.ps1
npm.cmd --prefix frontend run test:e2e
```

后一个命令使用空闲的 3100 端口，不复用不明来源服务；Windows 默认 Edge。Linux / CI 需先安装 Playwright Chromium，详见 README。

## 30 秒手动验收

1. 0–10 秒：打开首页，直接读“23 点后，扬声器下班”及其具体行为和执行接口。无需登录或填写信息。
2. 10–15 秒：点击“换一批示例规则”，条文立即变化，计数从 01/03 变为 02/03；继续点击可循环三套。
3. 15–25 秒：选择短租、社团，检查标题、时长、人数及五条规则同时更新。手机端空间选择在卡片下方。
4. 25–30 秒：点击“看一个四人宿舍示例”，恢复默认卡。全部页面数据来自预置规则。

这是演示路径设计，不代表已经做过评委用户调研或公网性能测试。
