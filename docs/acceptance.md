# 阶段验收

**当前交付为插入阶段 2.6。** 品牌、动画、换条抽屉及 133 项后端 / 40 项浏览器测试见 [stage-2.6.md](stage-2.6.md)。阶段 7 部署尚未开始。模型接入见 [stage-6.md](stage-6.md)，最终卡与导出见 [stage-5.md](stage-5.md)，创建与认领见 [stage-4.md](stage-4.md)。视觉文案来源见 [stage-2.5.md](stage-2.5.md)。以下为历史阶段记录。

## 阶段 1 目标

能够启动前后端，读取经过校验的规则库，维护 15 × 3 个行为水位和完整四列表。正式首页交互与房间流程留待后续阶段。

## 手动验收

1. 按 README 安装和启动两个服务。
2. 打开 `http://localhost:3000`：看到「临时宪法」、产品说明、一条规则与执行接口、三个空间简介。
3. 将浏览器调窄至手机宽度：文字不横向溢出，规则和接口可以完整阅读。
4. 打开 `http://localhost:8000/health`：看到 `status: ok`、服务名称和 `stage: 1`。
5. 打开 `http://localhost:8000/docs`：看到已实现的健康检查，而不是不存在的房间接口。
6. 停止后端后重新打开前端：首页静态内容仍可显示。
7. 查看 `docs/friction-matrix.md`：三个场景合计 15 个摩擦，每个 3 个具体行为选项，每行都有对应幽默条文和执行接口。

## 自动检查

运行 `scripts/check.ps1`，验证规则库与生成示例同步、后端检查和测试、前端静态检查与生产构建。规则库不合法时应拒绝启动，而不是静默丢弃错误条文。
