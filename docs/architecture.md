# 架构与阶段边界

## 产品目标

「临时宪法」只用于空间刚启用时的约定：把潜在摩擦写成可观察、可执行且不针对个人的行为条文。不提供冲突调解、评分、实名、惩罚或长期监督。

第一版每份宪法固定 5 条。每个摩擦点选一个行为水位，少于 5 个时生成前展示补充建议。至少一人认领即显示「已通过 · N 人认领」，这表示有人愿意执行，不表示全体一致同意。单人可以认领全部 5 条。

## 当前实现：阶段 6

```text
Next.js 首页（静态示例，不请求后端）
  ├─ /create 创建与边界确认
  ├─ /room/[code] 匿名认领与替换
  └─ /room/[code]/card 不可变最终卡、复制、PNG 与分享

FastAPI
  ├─ 启动时加载并校验规则库
  ├─ SQLite + Alembic 数据迁移
  ├─ 匿名房间、认领、替换、定稿快照
  ├─ 一次模型改写 → 严格校验 / 3 秒超时模板回退
  ├─ GET /health 与 /api 接口
  └─ /docs 与 /openapi.json

rule_library.json → 同步脚本 → 前端 examples.json（9 套，首页直接使用）
```

已实现持久化、完整房间流程与可选模型调用。当前本机没有模型配置；本地兼容 HTTP 接口测试通过，外部真实模型和公网尚未验证。`/health` 只检查服务存活，不能代表数据库连接持续健康或模型可用。开发启动时自动迁移，生产启动仅检查迁移版本。

## 目标架构

```text
浏览器 → Next.js / Vercel
              ├─ 内置示例与示例体验（完全本地）
              ├─ 创建、认领、最终卡与 PNG 导出
              └─ 同域 /api 转发
                    ↓
              FastAPI / Render
                ├─ 匿名身份、操作权限、房间与认领
                ├─ 固定行为 → 幽默改写 → 校验 / 模板回退
                ├─ PostgreSQL / Supabase
                └─ OpenAI 兼容接口（密钥只在后端）
```

前后端独立部署。同域转发减少跨域 Cookie 配置问题，但不替代后端权限检查、CORS 或限流。数据库与后端尽量选择相近区域。

## 技术与目录职责

| 部分 | 技术 / 职责 |
| --- | --- |
| frontend | Next.js App Router、TypeScript、Tailwind；浏览器展示和交互 |
| backend/app/api | HTTP 路由，不承载规则生成细节 |
| backend/app/core | 环境配置、数据库、迁移和匿名权限基础设施 |
| backend/app/schemas | 请求、响应和规则库校验结构 |
| backend/app/models | SQLModel 数据模型及不可变定稿快照 |
| backend/app/services | 规则库、房间事务、三层规则引擎与模型调用 |
| backend/app/data | 唯一维护的规则原始数据 |
| scripts | 本地安装、验收与静态数据同步 |
| docs | 决策、验收和部署说明 |

本地使用 SQLite，默认数据库为 backend/data/app.db。部署目标使用 PostgreSQL 和 psycopg。Alembic 迁移在容器启动时执行，通过 PostgreSQL 事务锁避免多个实例同时升级。真实环境验证见 [部署文档](deployment.md)。

## 已实现的数据与权限契约

- `Room`：空间、时长、群名、状态、版本与创建 / 定稿时间。学期第一版按 120 天计算，仅表示有效期。
- `Rule`：摩擦与水位、文本、接口、状态、顺序与版本；行为边界不因换笑话而变化。
- `Participant`：房间内匿名身份、昵称与浏览器身份关联。昵称仅供展示，不用于授权。
- `Identity`：浏览器级匿名凭证的 SHA-256 摘要及有效期；一个浏览器可加入多个房间，Participant 关联 Identity，避免新建房间覆盖旧房间身份。
- `Operation`：生成、确认替换和定稿的请求指纹与幂等编号；失败事务不留下成功回执。
- `Claim`：参与者对某个版本规则的认领，同一参与者重复认领不重复计数。
- 定稿快照：固定当时的规则、人数、群名、日期和宣誓句；分享页、复制与图片共用快照。

参与人数来自实际加入的匿名身份，不能用认领数替代。示例人数明确标为演示数据。浏览器以安全 Cookie 保存匿名凭证；创建者可以定稿，公开短码不是管理凭证。

Cookie 为 HttpOnly、SameSite=Lax、Path=/api，生产增加 Secure；默认有效期 180 天。同一浏览器清除 Cookie 或凭证过期后，不能恢复旧创建者权限，这是无需账户模式的已知边界。昵称可相同，但身份和权限不同。公开读取隐藏认领者昵称，定稿快照从不包含昵称。

未认领的规则可更换模板；更轻水位必须显示差异并确认。已认领规则的替换需创建者确认，应用后撤销旧认领，重新回到待议。已定稿内容不修改，换一批创建新草案。草案采用定时刷新、操作后刷新和版本冲突检查，第一版不引入 WebSocket。

阶段 4 草案页在可见时每 8 秒刷新，恢复焦点时刷新，也提供手动刷新；写操作期间暂停新轮询并作废旧读取结果。当前后端要求认领携带条文 version，生成和定稿携带房间 revision。SQLite 写事务使用 BEGIN IMMEDIATE，PostgreSQL 按房间加行锁，所有修改走同一锁顺序。读取使用一致性事务，避免一次响应中的房间、规则与认领来自不同状态。

生成、替换确认、定稿使用 Idempotency-Key；同编号同请求只执行一次，并返回房间当前状态，非历史响应快照。同编号不同请求返回 409。重复加入、重复认领不增加人数或次数。创建房间本身没有幂等协议，前端应禁止连点，并且不能自动重试创建请求。

所有写请求需要 X-CSRF-Protection: 1；带 Origin 时必须命中显式名单。浏览器通过前端同源的转发访问 API，生产 Cookie 限定 HTTPS。单进程写请求按连接 IP 每分钟限流，默认 60 次。代理可能让多个访问者共享额度，部署后需实际验证；扩容前需改用共享限流。/health 检查存活，/ready 检查数据库连接。

## 阶段 5 定稿与导出

创建者在五条均有认领后勾选确认；确认绑定当前 revision，房间发生变化即失效。前端使用已有 finalize 接口，写操作加同步锁和幂等编号。响应丢失时重新读取房间，若已定稿则提供最终卡入口；不自动再次提交。后端权限与数据逻辑保持不变。

`/room/[code]/card` 可公开阅读。`FinalConstitution` 仅接受 `CardSnapshot`；条文按快照 order 排序，人数、群名、期限和宣誓句均不读取可变房间字段。`cardPlainText` 共用同一快照生成完整文本，时间统一按 Asia/Shanghai 显示，不包含认领昵称。草案与缺失快照不显示为最终卡。

正常页面适配手机阅读，整卡模式将 720px 宽的卡缩放到当前可用宽高。PNG 由独立、对辅助技术隐藏的 720px 导出节点生成，使用相同卡组件与样式，html-to-image 按需加载，以 2 倍像素导出。等待本机字体就绪，不请求外部字体；导出等待上限 20 秒，失败时保留卡片并提供重试、整卡截图和复制全文。图片在浏览器内生成，不上传服务器。

复制受限时展示可选中的完整只读文本；分享优先调用浏览器分享面板，不支持或调用失败则复制最终卡链接，用户取消不报成功。新草案入口保留空间参数，不能修改已定稿快照。

## 阶段 6 模型调用边界

现有同步生成路由先完成权限、状态、版本、建议确认及幂等检查，再在同一事务内调用 rule_engine.generate_rules。llm.rewrite 通过 AnyIO 使用服务已有事件循环执行一次 httpx 异步请求，3 秒总截止时间覆盖连接与完整读取；无配置直接返回，不重试、不重定向。保留原有 SQLite 写事务 / PostgreSQL 房间行锁，避免并发双调用及重复插入。

模型只收到五个规则库摩擦、明确动作与接口，不收到群名、昵称、房间码和凭证。严格验证模型条目的固定部分，再以可信 action/hint 组装标题，单条不合法回退该条；请求失败整份回退。rule.source 取 llm/template，替换条文始终回到 template。无数据库结构变更，原草案和定稿快照不更新。

当前事务最多因模型等待增加约 3 秒，SQLite 其他写请求可能排队，需在阶段 7 结合 PostgreSQL 和真实负载验证。进程崩溃发生在第三方返回与事务提交之间时，无法对外部提供商保证跨进程恰好一次；正常重试、并发和已持久化模板回退不会再次调用。模型自检与词语过滤不能完全证明中文语义安全，仍需真实模型内容抽样。

## 阶段 2.6 展示层与兼容性

产品展示名称改为「先说好」。保留既有路由、Cookie、存储键、房间编号、三层规则引擎和 Next 同源代理。新展示层使用 `playful.css` 的颜色/字体变量、`BrandMark` 和 `presentation.ts` 图标映射，无外部字体请求或新增运行依赖。

首页默认只展开第一条，原生 details 保留全部文本及无脚本阅读能力；动画只用 transform / opacity，减少动态效果时跳过开场与撒花。创建流程仍是空间、边界、确认三步。最终卡仍从 immutable snapshot 读取，只有新增定稿口号更新，不迁移旧快照。

`SwapSheet` 是独立原生 dialog：正文滚动、操作区固定在抽屉内，背景 inert、Esc/遮罩可取消、键盘焦点循环，取消请求后恢复触发按钮焦点。预览只读且可中止；只有确认后才修改规则。轮询发现条文版本或认领人数变化时禁用旧确认；apply 携带 `expected_claim_count` 在现有房间锁内验证，以覆盖尚未轮询到的新增认领。该字段向后兼容，不改数据库结构。认领动画只在保存成功后播放。

## 故障边界

1. 首页与本地示例始终不依赖后端或模型。
2. 后端正常但模型失败：使用模板生成并正常保存真实房间。
3. 后端不可用：创建页显示重试与回首页示例的入口，草案页保留上次读取结果并提示刷新；首页本地示例正常，不能显示真实房间保存成功。
4. 3 秒仅是模型调用预算，不包含冷启动、数据库连接和用户网络耗时。
5. 每次主动生成最多一次模型调用；不自动重试。其他操作不调用模型。

## 部署与验证边界

目标为 Vercel + Render + Supabase；Dockerfile、render.yaml、部署文档在阶段 7 完成。比赛前检查实际访问地区、移动端和后端冷启动。任何付费资源或缺少授权的账户操作在出现实际阻塞时处理，不假定已有额度或凭证。
