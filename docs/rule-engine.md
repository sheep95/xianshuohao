# 规则引擎

## 当前能力与后续能力

阶段 6 已实现模型约束改写与服务端校验，保留此前 JSON 规则库、模板草案、持久化、认领、换条与定稿。静态示例导出和 GET /api/examples 共用 build_examples，始终不联网。模型未配置或失败时仍能生成完整草案。

规则库是唯一来源：`backend/app/data/rule_library.json`。完整四列表见 [friction-matrix.md](friction-matrix.md)。

## 第一层：真实摩擦库

库包含 15 个摩擦原型，每个恰好 3 个行为水位；3 个空间各有 5 个不同摩擦的默认选择。水位是具体可选边界，不要求机械地排成严格 / 中等 / 宽松，也不能在未确认时擅自降低阈值。

| 字段 | 含义 |
| --- | --- |
| schema_version | 当前库结构版本 1 |
| spaces | 空间名称、默认时长、说明及 5 个默认选择 |
| frictions[].key / title | 稳定摩擦标识与简短展示名称 |
| real_friction | 真实摩擦解释，供内容维护和后续服务内部使用 |
| space_types | 适用空间标识 |
| levels[].id / label | 当前摩擦内唯一水位标识与选择文案 |
| action | 固定动作与条件，不能让模型改写成模糊态度 |
| execution_hint | 做不到时最低成本的替代动作和提醒接口 |
| humor_variants | 至少两个预置幽默表达，不针对个人 |

空间标识为 `shared_home`、`short_stay`、`club_room`。时长分别为 7 天、3 天、120 天；页面显示「一周」「三天」「一学期」。一学期按 120 天是第一版计算约定，不代表长期监督功能。

静态条文组装规则：`幽默表达 + 空格 + action`。固定动作必须始终出现在最终条文中。执行接口单独显示，不用表情替代应执行的动作。

结构校验拒绝未知字段、空白字符串、重复标识、错误默认引用、跨场景选择和超过长度限制的内容。结构校验只能保证数据契约，不能证明中文语义一定可执行；全部 45 个水位仍须人工审阅。

## 静态示例同步

`scripts/sync_examples.py` 先加载经过校验的库，再为每种空间生成 3 套、每套 5 条的示例，输出到前端 `src/data/examples.json`。首套使用该空间默认选择，另外两套确定性切换摩擦、水位与幽默表达。

示例明确带有 `is_example: true`。示例人数只是演示数据，不能写入真实房间参与人数。生成算法不使用网络、当前时间或随机状态，相同库内容产生相同结果。

```powershell
.\backend\.venv\Scripts\python.exe scripts/sync_examples.py
.\backend\.venv\Scripts\python.exe scripts/sync_examples.py --check
```

校验模式只读，数据陈旧时返回非零状态，供统一检查脚本调用。首页直接导入这些 JSON，不先调用后端获取示例。

## 第二层：约束式幽默改写（阶段 6）

仅在用户主动点击「生成我的宪法」时调用一次兼容 OpenAI 的接口，整份 5 条放入同一次请求。服务端读取 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`；没有密钥直接使用模板。

模型输出包含内部摩擦解释、完整条文和执行接口。可编辑的范围只有标题；正文与接口必须逐字复制。后端验证后仍用可信库动作句组装展示条文，内部解释不保存、不放入公开响应。群名、昵称、房间码、Cookie 不进入提示词，不根据具体个人编写笑话。

完整系统提示词位于 `backend/app/services/llm.py` 的 SYSTEM_PROMPT。五条合并调用 `LLM_BASE_URL/chat/completions`，使用 `response_format=json_object`、`max_tokens=1800`、`stream=false`。不使用 SDK 自动重试，不跟随 HTTP 重定向，不读取环境代理；不支持这些请求参数的提供商直接回退。

模型输出格式如下；每条字段必须齐全且不能增加其他字段：

```json
{
  "rules": [
    {
      "friction_key": "night_sound",
      "level_id": "quiet_2300",
      "real_friction": "必须逐字复制库中的内部摩擦解释",
      "text": "幽默标题。 必须逐字复制用户选择的 action 全文",
      "execution_hint": "必须逐字复制用户选择的 execution_hint 全文"
    }
  ]
}
```

上面省略了其他四条，仅说明结构；真实响应必须为五条，按输入顺序一一对应。

提示词必须要求模型在同一次回答中自检并重写不合格条目：

1. 是否有可观察动作或阈值？
2. 不想或不能遵守时，是否存在不需要解释的最低成本动作？
3. 读给不在场的人听，是否会被理解为在阴阳他？
4. 是否出现惩罚、羞辱、人身攻击、实名指向或模糊的道德要求？

任一不过则在本次回答内重写，不追加模型请求。后端不把模型声称“已自检”当作通过证据。调用总预算 3 秒；asyncio.timeout 包住连接、读取完整响应及解析，逐块返回也不能续期。同步 FastAPI 工作线程通过 AnyIO 回到服务已有事件循环等待，避免每次新建事件循环退出时等待 DNS 线程结束。超时取消请求并关闭连接，没有后台补写或迟到替换。

## 第三层：服务端校验与回退（阶段 6）

检查输出结构、条目数量、顺序对应的摩擦 / 水位、内部摩擦、长度、固定动作和执行接口。拒绝重复 JSON 键、非有限数值、代码围栏、额外字段、截断回复、拒答以及超过 64 KiB 的提供商响应。单条按严格 Pydantic 模型校验，动作与接口逐字比较。

标题限定 4–30 个中文字符/中文标点，结尾句号，并禁止新增数字/数量、人称/个人指向、惩罚羞辱词、命令/例外表达及常见拟人化说教词。过滤只作用于模型标题，不将审阅过的固定阈值误删。使用规则库中的原水位表达作为逐条模板替换表，不新增行为门槛。

- 单条非法：该条用原水位的预置表达替换。
- 超时、连接错误、返回体无法解析：全部使用模板。
- 无密钥：全部使用模板，不发请求。
- 任何回退都保留用户选定水位与接口，不能把失败当作降低边界的理由。

source=llm 仅代表该条通过程序校验并采用模型标题，不代表语义审核绝对可靠。模型校验不是对自然语言的数学证明，中文同音隐喻和未知攻击表达仍可能漏检；保守过滤也可能把安全标题退回模板。缩小模型可编辑区域、维护可信模板和人工内容审核共同减少风险。上线前需用实际模型抽样审核文案。

启用该模块的 INFO 日志时，只记录固定原因码、采用数量和总数，不记录原始输出、异常详情、提示词或密钥。3 秒不包括数据库锁等待、冷启动和用户网络。当前事务内执行调用，保留原有幂等及并发正确性：SQLite 会短暂阻塞其他写请求，PostgreSQL 锁同一房间；规模化时需持久化生成任务设计，不能简单移除锁后重复调用。若进程在外部调用完成后、数据库提交前崩溃，后续用户重试可能再次调用；第三方与数据库无法获得跨系统恰好一次保证。

## 认领与换条约束（阶段 2 后端已实现，阶段 4 接入页面）

默认只换表达，原动作条件不变。选择更轻水位时先显示差异并确认；已认领的规则由创建者确认替换，替换后原认领全部失效。5 条均有人认领后才能定稿，认领仅代表愿意执行，不宣称全体一致同意。

所有换条使用模板，不额外请求模型。定稿后修改另开草案，已经分享的快照保持不变。

创建房间时，少于 5 个选择会补齐本场景默认项，响应逐项标注 suggested 并展示动作及接口。生成前必须传 confirm_suggestions=true 确认；提交完整 5 个选择则不需要补充确认。前端正式创建前可使用公开规则库调整完整选择。

交换条文先用 mode=preview 得到新旧动作、是否改变边界、需撤销多少认领；mode=apply 要求 confirmed=true 和幂等编号。替换后 version 增加，status 变为 debating。认领该版本后 status=claimed；未认领的初始草案为 pending。

## 阶段 2.5 已确认的文案规范

标题负责说破潜台词：直接、带一点戏剧性，不用物品拟人化表达，不讽刺具体个人。正文负责可观察动作和阈值，执行接口负责最低成本的下一步，不要求解释或道歉。

本轮重写 45 个水位的 90 个幽默标题与 45 个执行接口，替换三条经用户确认的正文。其余动作句、标识、默认水位和生成逻辑保留；静态示例通过现有 scripts/sync_examples.py 同步。完整变更与验收见 stage-2.5.md。
